MECHANISM
---------
- Driver: Textual's headless driver, `App.run_test(size=..., notifications=True)`,
  on the shipped `TaskboardApp`, each run on a fresh temp board
  (`tempfile.mkdtemp()`; no user board touched).
- Input is real: `pilot.press(<key>)` for enter / down / pagedown / esc / d / x / P /
  f / S, and `pilot.click(offset=(x, y))` (a real mouse event at the screen cell
  where the project line was painted). No `.focus()`, setter or action call
  stands in for a key. Task selection is the app's own default (the first task;
  one task per board), not a setter.
- Read-back is the painted frame: `screen._compositor.render_strips(...)` after
  layout (the composited cells, toasts included), cut to the modal's region.
  Styles are read off the painted segments (bold flag, foreground colour). The
  app renders "dim" as a blended foreground colour (#606a75 / #a1a1a1), so dim is
  judged by colour against the base run, not by the dim flag.
- Note on the mechanism: `run_test` defaults to `notifications=False`; with the
  default, no Toast is mounted and a toast criterion reads nothing. The first
  pass of this walkthrough hit that (0 toasts), and it was re-run with
  `notifications=True`. The batch's own toast tests already pass that flag.
- The driver is a scratch script outside the repo (walk.py, sha256
  205439710e833cfc727f68cecb1ef3348d0ddd4a8454a158c27050545873db26); its output
  is excerpted below. Temp paths are redacted to <tmp>.

FINDINGS
--------
UXV-1 minor (= UX-3, operator's call): the details title now has 2 blank rows
  above it and 0 below; the base had 1 below (the grid's first-row margin made
  it). The change removed the gap under the title along with the per-row
  margin. Legible, but the title reads as the first grid row.
UXV-2 minor, pre-existing (same in base captures): at 80x24 the scrollbar thumb
  ("▆▆") paints 2 cells inside the right border, in the content padding, with no
  visible track; the only cue that Images sits below the fold. Not introduced
  by this batch.
UXV-3 minor: the unreadable-team.json toast puts the full shared-folder path in
  the middle of the sentence; a long path takes a toast line of its own and
  splits "could not / be read". Legible; putting the path last (or clipping it)
  would keep the sentence whole.
No blocking finding.

THE THREE ACTS
--------------
- Automated walkthrough: performed — the criteria above, via Textual's headless
  driver with real keys and mouse, read off the composited frame.
- Expert inspection: performed — a cognitive walkthrough by this reviewer (not a
  user) of the tasks "read a task's fields", "read a long project", "confirm a
  delete / archive", "manage projects / phases", "read the standup", "start in
  team mode with a bad shared file", against the criteria above.
- Evaluation with users: not performed — this team is one person and no user of
  this surface exists outside it. The operator's PV-1 / UX-3 / UX-4 verdict on
  the captures is an operator decision, not a user evaluation.
- Limits: the headless driver does not exercise a real terminal's font,
  colour profile or wide-glyph handling; ":smile:" was checked as literal text,
  no real emoji glyph was walked; sizes walked: 140x40 and 80x24 only.

RECOMMENDATIONS (the operator decides)
--------------------------------------
- PV-1 (one row per field, no blank row between, long values wrap; edit modals
  untouched): ACCEPT. It is the fix: the base painted four of five fields blank.
  Compact rows keep notes and URLs above the fold at 140x40 and the five fields
  visible at 80x24 without scrolling.
- UX-3 (a gap under the title): ACCEPT, cost-neutral if done by moving one of
  the two blank rows above the title to below it, rather than adding one. It
  restores the base's separation (UXV-1) without pushing Images further below
  the fold at 80x24.
- UX-4 (label column 20 -> 10): ACCEPT. The longest label, "Priority", is 8 cells;
  10 leaves a 2-cell gap. At 80x24 the value column gains 10 cells, so the
  89-character name wraps on 2 rows instead of 3 and one more row of
  notes/URLs fits; the eye travels 10 fewer cells from label to value. Risk:
  none seen — no label is longer than 8 cells today; a future longer label
  would need the column re-checked.
