## 2. Overall description

### 2.1 Product perspective
Today the app opens one board file — `~/.taskboard/board.json`, or another with `--board PATH` — and cannot change it while it runs. This batch adds a registry of board files, a home that shows them as cards, the open board's chip, and the move of a project between files. Every board keeps its own file, history, images, reports and settings (team mode included), so the board views, the presentation, the report and team sync are unchanged: they read whichever board is open.

### 2.2 Product functions
1. The app knows several boards; today's board is `Main`, untouched; a new board lives in its own folder.
2. The open board is named in every view's head row (with more than one board).
3. The home shows every active board as a card — its open, late and due-this-week counts, a 4-week due strip, its next dues, its projects — and opens one.
4. Boards are created, renamed, recoloured and archived from the home.
5. A project moves, with its tasks, history and images, from one board to another; the links that would cross boards are listed, dropped and logged.

### 2.3 User characteristics
The operator alone (`username_subject`), keyboard only, in a terminal usually at 160×45 or 118×30, at times at 80×24; boards for several clients and courses plus personal tasks.

### 2.4 Constraints
Textual + Rich as shipped; no new dependency; every head row exactly the view's width; every board name, project name and task title painted literally (escaped before it enters markup, or appended to a `Text` as plain text — S1/C8); the registry and every board file written atomically; nothing under `~/.taskboard/` moved, migrated or created at the launch of a one-board user; tests never read or write the real `~/.taskboard` (a suite-wide seam points `Path.home()` at a temporary folder); the round's committed files are not rewritten; synthetic data only; the operator's name nowhere.

### 2.5 Assumptions and dependencies
The round's fixture (`prototypes/multi_board/fixture.py`) is copied into `tests/multi_board_fixture.py` (its four boards and registry unchanged) so the suite does not import a prototype. Microsoft Edge is present for the PNG renders of the captures (`views._find_msedge()`). The time-dependent parts (`opened <ago>`, the date in the home's title, the registry's `last_opened`, the move's backup and log names) are tested with the calendar and the clock frozen at every module that reads them: `app.date`, `app.datetime`, `models.date`, `views.date`, `modals.date`, `__main__.datetime` (qa-reviewer QA-2).

## 3. High-level requirements (HLR)

### HLR-2201 — A registry of boards, read without failing
- **Traceability:** US-2201
- **Ledger:** LED-2026-10-20-batch-01.1, LED-2026-10-20-batch-01.2
- **Statement:** The system shall keep a registry of boards in `boards.json` beside the default board file — per board an id, a name, a colour, the board file's absolute path, when it was last opened and whether it is archived, and the id of the board opened last — and shall read it at start without raising, every string in it cleaned of control characters as the board file is: a missing file shall be read as a registry holding only the default board (`main`, `Main`); an unreadable file (not JSON, or not an object holding a `boards` list) shall be copied byte for byte to the first free name of `boards.json.corrupt`, `boards.json.corrupt-2`, … (an empty file excepted), read as that same registry and named in a notice; an entry shall be skipped when its path is not non-empty absolute text or resolves to the path of an earlier entry; an id that is not non-empty text of ASCII letters, digits, `-` or `_`, or repeats an earlier id, shall be replaced by a unique slug of the name; a name that is not non-empty text once cleaned shall be the board file's name, and a name shall be cut to 60 characters; a colour shall be read by the project colour rule; a last-opened time that is not an ISO time shall be none; an entry shall be archived only for the JSON `true`; a registry left with no entry shall hold only the default board. The registry file shall be written atomically, when the operator changes the registry (a board registered, created, edited or archived) and when a board is opened while the registry holds more than one board or its file exists — with one board and no file nothing shall be written, and after an unreadable read nothing shall be written at an opening, only at an operator's change.
- **Rationale (informative):** P1 ("validated on load like the board loader; missing file = registry of just Main; writes atomic"); a one-board user sees no new file.

- **`--board PATH` registers the path (P4).** Running `taskboard --board` on a copy (as the link-migration error suggests) adds that copy to the registry, and the next plain start shows the home; `x` on the home archives it. Recorded in the README.
- **Two app instances.** Two running apps can each write `boards.json` and the same board file; the last write wins, as with the board file today. Not locked (§1.2).
- **A board file deleted under the registry.** Its card reads `file missing`, opening it warns and opens nothing, and a start passes over it to the next board with a file (HLR-2202, HLR-2204); `taskboard --board PATH` on a missing path still creates it, as `--board` always has.
- **Moves are not undoable (`u`).** The confirmation says so; the `.pre-move-<date>` copies are the way back (the commission).
- **A board's start-up modals over the home (ux-reviewer UX-5).** At launch the team identity picker and the milestone offer of the board opened last sit above the home and answer for that board, which they do not name; rare (a first team start, a one-time offer) — accepted and recorded.
- **The home's reads are not measured for speed (ux-reviewer UX-8).** Each board file is read once when the home opens; local files of a few hundred tasks — out of scope.
- **Registry paths are the operator's own (security S-5).** The home reads every active board's path at opening; a network path means a network read; a hand-edited path is opened like `--board`'s and never moved or deleted by the app.
- **Phases differ between boards.** A move whose tasks' phases the target lacks is refused; the operator adds the phase there (`f`) first.
